# چاپ لیبل شماره موتور

`POST /api/enter-engines/{id}/print`

- نیازمند احراز هویت `auth:sanctum`، کاربر فعال و مجوز `enter-engines.print` است.
- پارامتر `id` شناسه رکورد `EnterEngine` است؛ بدنه درخواست لازم نیست.
- شماره موتور از `engine_no` رکورد خوانده می‌شود. IP و شماره موتور ارسالی در بدنه نادیده گرفته می‌شوند.
- یک لیبل با عرض **۱۰۰ میلی‌متر** و ارتفاع **۲۰ میلی‌متر** در قالب `ZPL` تولید می‌شود؛ بارکد `Code 128` بالا و متن شماره موتور زیر آن قرار می‌گیرد. VIN و id روی لیبل چاپ نمی‌شوند.
- شماره موتور خالی، دارای کاراکترهای غیر ASCII یا بارکد بزرگ‌تر از فضای لیبل با `422` رد می‌شود. صفرهای ابتدای شماره حفظ می‌شوند.
- داده‌های `ZPL` مستقیماً و به‌صورت synchronous به `192.168.147.193:9100` ارسال می‌شود؛ صف و worker لازم ندارد. آدرس از `ENGINE_LABEL_PRINTER_IP` قابل تنظیم است.
- خروجی مخصوص **Gainscha GI-2408T با رزولوشن ۲۰۳ DPI (۸ نقطه بر میلی‌متر)** است: یک تصویر سیاه‌وسفید ۸۰۰×۱۶۰ نقطه‌ای شامل بارکد و متن، با دستور `^GFA` و یک نسخه چاپ (`^PQ1`) ارسال می‌شود. شماره موتور به تصویر تبدیل می‌شود تا کاراکترهای آن نتوانند دستور چاپ تزریق کنند.
- مطابق [مشخصات سازنده](https://gainscha.com.tw/product/81.html)، این دستگاه از `ZPL / ZPL II` پشتیبانی می‌کند؛ PDF خام دیگر در این مسیر ارسال نمی‌شود. زبان فعال دستگاه باید `ZPL` یا تشخیص خودکار سازگار با آن باشد. کاغذ ۱۰۰×۲۰، نوع سنسور و ریبون باید روی دستگاه درست تنظیم شده باشند. سرور API باید به شبکه پرینتر دسترسی داشته باشد.
- مرجع قالب تصویر: [ZPL Programming Guide، دستور `^GF`](https://cpws.zebra.com/cpws/docs/zpl/zpl-zbi2-pm-en.pdf). این تغییر مربوط به `printLabel` است؛ Jobهای قدیمی `PrintEngineLableJob` و `PrintSynchronousJob` همچنان خروجی PDF قبلی خود را دارند.
- `200` فقط پایان ارسال داده به سوکت پرینتر را اعلام می‌کند؛ چاپ فیزیکی را تأیید نمی‌کند. قطع ارتباط ممکن است پس از دریافت بخشی از داده رخ دهد؛ پیش از تکرار درخواست، وضعیت پرینتر بررسی شود.
- فایل موقت پس از موفقیت یا شکست ارسال حذف می‌شود.
- اگر `printers.engine_label.ip` وجود نداشته باشد، `null`، خالی یا از نوع غیررشته‌ای باشد، پیش از تولید لیبل و ارسال به چاپگر، پاسخ `502` برگردانده می‌شود؛ علت تنظیماتی در لاگ ثبت می‌شود.

برای رفع خطای تنظیمات روی سرور، ابتدا از وجود فایل `config/printers.php` در نسخه مستقر و مقدار صحیح `ENGINE_LABEL_PRINTER_IP` در محیط سرور مطمئن شوید. سپس کش تنظیمات را بازسازی و مقدار بارگذاری‌شده را بررسی کنید:

```bash
php artisan config:cache
php artisan config:show printers
```

خروجی باید `engine_label.ip` را با آدرس واقعی چاپگر نشان دهد. در صورت استفاده از Octane، پس از تغییر تنظیمات `php artisan octane:reload` نیز اجرا شود.

برای ثبت مجوز نام مسیر، مطابق روال پروژه `php artisan permission:update` اجرا و سپس مجوز به نقش موردنظر تخصیص داده شود. این دستور طبق رفتار موجود پروژه، مجوزهای قدیمی خارج از فهرست خود را نیز حذف می‌کند.

نمونه درخواست:

```http
POST /api/enter-engines/123/print
Authorization: Bearer <token>
Accept: application/json
```

پاسخ موفق (`200`):

```json
{
  "message": "داده‌های لیبل به چاپگر ارسال شد.",
  "data": {
    "id": 123,
    "engine_no": "00123ABC456789",
    "printer_ip": "192.168.147.193",
    "label_size_mm": [100, 20]
  }
}
```

سایر وضعیت‌ها: `401` بدون احراز هویت یا کاربر غیرفعال، `403` بدون مجوز، `404` شناسه ناموجود، `422` شماره موتور نامعتبر و `502` خطای ارسال به چاپگر. خطاهای تولید تصویر لیبل خطای داخلی سرور هستند. چاپ فیزیکی روی دستگاه واقعی هنوز تأیید نشده است.
